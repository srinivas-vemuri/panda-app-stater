🐼 Panda PHP Blank App

A lightweight PHP starter with settings, authentication, and PWA capabilities.

Introduction

Panda PHP Blank App is a lightweight, modular PHP starter framework designed for rapid development of small to medium web applications. It provides essential features such as authentication, settings management, navigation control, email integration, and Progressive Web App (PWA) support — all built on a simple procedural PHP foundation with SQLite for storage.

This project is intended for developers who prefer simplicity over heavy frameworks but still want a production-ready base with best practices in security, maintainability, and scalability.

Features Overview
  • Authentication & Roles: Built-in user login system with three tiers — Regular User, Admin, and Super Admin.
  • Settings System: JSON-based configuration stored in /inc/settings.json with auto-creation and validation.
  • Navigation Manager: Dynamic navigation links stored in settings, with mobile and admin visibility toggles.
  • Email Integration: PHPMailer with automatic SMTP detection and fallback to PHP mail().
  • Branding Controls: Upload logos, set theme colors, and configure header/footer design.
  • PWA Ready: Generates manifest.json and service worker automatically when enabled.
  • App Cleanup: Secure utility to reset or uninstall the app safely.
  • Documentation & Modularity: Clean file structure, self-documenting code, and clear separation of concerns.
Installation & First Setup

Installing Panda PHP Blank App is straightforward:

  1. Upload all files to your web server or local environment.
  2. Ensure PHP has write permissions in the application directory.
  3. Access the app through your browser — the installer will automatically detect the missing database and initialize it.
  4. Create your Super Admin account, which grants full system access and developer privileges.
  5. Once installed, navigate to settings.php to configure app name, branding, email settings, and PWA options.

The installer automatically creates:

  • data.sqlite — the main database
  • inc/settings.json — configuration file
  • Default Super Admin account (created during installation)

Authentication & Role System

The Panda PHP Blank App includes a built-in multi-tier authentication system with secure session handling and role-based access control.

User Types
  • Regular User (user_type = 0) — Access only to basic application areas.
  • Admin (user_type = 1) — Can manage users, access settings, and view analytics.
  • Super Admin (user_type = 2) — Full access including developer tools and advanced configurations.
Session Handling

Upon successful login, the user’s user_type is stored in the session and used to determine page permissions. Protected pages include inc/header.php, which automatically checks for an active session and redirects unauthenticated users to the login page.

Security Rules
  • Only Admins and Super Admins can access the Settings panel.
  • Admins cannot create or promote Super Admin accounts.
  • Session hijacking is mitigated by regenerating session IDs on login.
Settings Management System

All configuration in Panda PHP is stored in a single JSON file located at /inc/settings.json. The settings system automatically creates this file if it doesn’t exist and loads it on every request through helper functions.

Core Functions
  • getSettingValue($field) — Retrieves a single setting value.
  • getSettings($group) — Loads all settings under a group (e.g., basic, branding).
  • updateSettings($updates) — Saves modified settings back to the JSON file with validation.
  • handleFileUpload() — Securely processes and stores uploaded files (logos, icons).
Groups & Organization
  • basic — Core app configuration (name, URL, index page).
  • branding — Visual identity and color scheme.
  • pwa — Progressive Web App settings.
  • email — SMTP and email parameters.
  • navigation — Menu structure and visibility settings.

Each group is displayed as a separate tab in the admin settings.php interface. Only users of type Admin (1) or Super Admin (2) can modify settings.

The Basic Settings tab defines your application’s core identity and behavior. These fields are stored under the basic group in settings.json.

Branding & Design

The Branding tab controls your application’s visual identity — logos, favicon, and color scheme. Uploaded images are automatically validated and stored in /assets/logos/ and /assets/icons/.

Logos
  • Square Logo (512×512 PNG): Used for app icons, PWA assets, and favicon generation.
  • Rectangular Logo (≈350×150 PNG): Used in headers and large display areas.

When you upload a new logo, existing logo files are automatically replaced, and settings.json is updated with the new filenames.

Color Settings
  • appthemecolor — Primary brand color.
  • appheadercolor — Navbar background color.
  • appfootercolor — Footer background color.

All colors are applied dynamically as CSS variables to maintain consistent styling across the app. You can preview colors directly in the admin panel before saving changes.

PWA Configuration & Manifest

Panda PHP Blank App supports Progressive Web App (PWA) functionality, enabling your web application to behave like a native app when installed on mobile or desktop.

Key Settings
  • appispwa — Toggle to enable PWA mode.
  • appicon192 — Small app icon (192×192 PNG).
  • appicon512 — Large app icon (512×512 PNG).
  • appdisplay — Display mode (e.g. standalone, minimal-ui, browser).
  • appfevicon — Favicon icon for browsers (auto-linked in <head>).
Manifest & Service Worker

When appispwa is enabled and all required icons and fields are available, the system generates:

  • manifest.json — Built dynamically using app settings.
  • service-worker.js — Registers caching and offline behavior.

The start_url in the manifest is generated from: appurl + appindexpage, ensuring the app opens at the correct entry point.

Future Additions
  • Automatic regeneration of manifest and service worker when settings change.
  • Visual “Generate / Regenerate PWA Files” button in the PWA tab.
Email System (PHPMailer Integration)

The Panda PHP Blank App includes a powerful, automatic email system based on PHPMailer. It handles user notifications, password resets, and admin alerts through a unified sendmail() function.

Automatic Mode Switching

The sendmail() function detects your configuration and switches automatically:

  • If SMTP settings exist → sends via PHPMailer using TLS/SSL.
  • If SMTP settings are missing → falls back to PHP’s native mail() function.

Email Templates & Notifications

The system includes modular, reusable HTML email templates stored under /inc/templates/. Each email is rendered using renderTemplate() and wrapped in a consistent layout via wrapEmailHtml().

Available Templates
  • email_user_welcome.php — Sent to users upon registration.
  • email_admin_new_user.php — Sent to all admins when a new user registers.
  • email_password_reset.php — Sent when a password reset is requested.
  • email_password_reset_success.php — Sent after a successful password reset.
Core Rendering Functions
  • renderTemplate($name, $data) — Loads a template and replaces placeholders with provided data.
  • wrapEmailHtml($content, $subject) — Wraps an email body in a styled HTML frame with consistent branding.
  • sendmail($to, $subject, $message, $from, $isHtml) — Sends the rendered email using PHPMailer or PHP mail().

Each template includes inline CSS for compatibility across major mail clients. You can preview any template in your browser by appending ?preview=1 to email_test.php.

Tip:

Ensure appadminemail, appurl, and appemailsignature are configured correctly in settings — these fields are used dynamically in every template.

App Cleanup Utility

appcleanup.php is a secure reset tool that deletes all local app data and restores the system to a “fresh install” state. It is intended for development and testing environments — not production.

Security Requirements
  • The cleanup script is protected by a 16-character alphanumeric security code.
  • This code must be set manually inside appcleanup.php:
$securitycode = "A1B2C3D4E5F6G7H8";

To execute cleanup, visit:

https://yourdomain.com/appcleanup.php?code=A1B2C3D4E5F6G7H8
What It Removes
  • Database file: data.sqlite
  • Settings file: inc/settings.json
  • Uploaded assets: logos, icons, and other generated files
  • All user session data

The script confirms successful cleanup with a clear “✅ Cleanup Complete” message. Invalid or missing codes trigger a 403 Access Denied message for safety.

Optional future feature: a “dry run” mode to preview what will be deleted before confirming.

Redirect Logic & Base URL Handling

The system uses two complementary fields to control navigation flow and app entry:

  • appurl — Defines the absolute root of your installation (e.g., https://marketing.our-church.com/cleanapp/).
  • appindexpage — Defines the logical “starting page” of your app (e.g., index.php or first.php).
Core Helper Function
redirectToAppStart();

This function automatically redirects users to the configured start page using these two fields. For example:

// Example
redirectToAppStart(); // Redirects to https://yourdomain.com/cleanapp/dashboard.php
Usage
  • In login.php: if the user is logged in, redirect to their start page.
  • In index.php: redirect non-logged-in visitors to the configured app index page (if public app).
  • Used also by the PWA manifest to determine start_url.

This system allows the same codebase to serve both private apps (admin dashboards) and public-facing tools (e.g., a public data viewer) simply by changing settings — no code edits needed.

User Management

User Management allows Admins and Super Admins to view, edit, and control user accounts. The interface provides role management, activation toggles, and password resets.

Capabilities
  • Super Admin (2): Full access, can manage all users, including other admins.
  • Admin (1): Can manage users but cannot create or promote Super Admins.
  • Regular User (0): Can view and edit their own profile only.
Core Pages
  • usermanagement.php — Main user listing and status control.
  • useredit.php — Edit user details, including name, email, password, and role.
Business Rules
  • Super Admin role is hidden from Admins in dropdowns.
  • Users cannot edit their own user_type or deactivate themselves.
  • Passwords are stored as MD5 hashes (upgradeable to stronger hashing later).
Utility Functions
  • get_admin_emails() — Returns all Admin/Super Admin emails for system notifications.
  • generate_unique_user_id() — Creates random alphanumeric IDs for users.
Registration & Login Flow

The authentication flow consists of registration, login, and password reset processes. Each step is designed for simplicity and security.

Registration (register.php)
  • Registration form validates all inputs (username, email, password).
  • Checks for duplicates before creating a new account.
  • New users are initially inactive (user_status = 0) until approved by an Admin.
  • Welcome email is sent to the user, and an alert email goes to all Admins.
Login (login.php)
  • Authenticates users via email or username and MD5 password hash.
  • Inactive users cannot log in.
  • Successful login regenerates session IDs to prevent fixation.
  • Redirects to appindexpage after login.
Password Recovery
  • forgotpassword.php — Generates a 6-character reset code and emails it to the user.
  • resetpassword.php — Allows resetting the password using the emailed code.
  • Both emails use the templating system for consistent branding.

Registration and password reset pages automatically respect the RegistrationActive setting and SMTP configuration. If registration is disabled or SMTP isn’t configured, the system provides user-friendly notices.

Footer & Header Rendering

The user interface dynamically renders headers, logos, and footers using stored settings. This ensures your app branding is consistent across all pages.

Header Rendering
  • renderSmallHeaderLogo() — Displays the rectangular logo (header logo).
  • Background color uses appheadercolor from settings.
  • If StickyHeader = 1, the header remains fixed on top.
  • Clicking the logo redirects to appurl if available, or # otherwise.
Footer Rendering
  • Footer text is loaded from appfootertext.
  • HTML tags are rendered safely (allows links and formatting).
  • Background color uses appfootercolor from settings, with fallback to soft gray.

Example usage in header.php:

<nav <?= renderNavClassStyle(); ?>>
  <a class="navbar-brand d-flex align-items-center gap-2" 
     href="<?= getSettingValue('appurl') ?: '#' ?>">
    <?php renderSmallHeaderLogo(); ?>
    <span><?= getSettingValue('appname') ?: 'Your App Name' ?></span>
  </a>
</nav>

Example usage in footer.php:

<footer class="text-center py-3 small" 
        style="background:<?= getSettingValue('appfootercolor') ?: '#f8f9fa' ?>">
  <?= getSettingValue('appfootertext') ?: '&copy; Your App' ?>
</footer>
Database Administration (phpLiteAdmin Integration)

Panda PHP Blank App ships with an optional lightweight database administration tool — phpliteadmin.php — for direct inspection and management of your SQLite database.

Purpose

This tool allows developers and administrators to:

  • View and edit tables, records, and schema.
  • Run SQL queries directly against data.sqlite.
  • Inspect system data such as users, settings, and logs.
Access & Authentication

The file is located at:

https://yourdomain.com/cleanapp/phpliteadmin.php

By default, access to phpLiteAdmin is unrestricted after installation, so you should immediately set a password inside the file for security:

// Inside phpliteadmin.php
$password = "your-secure-password";

This password protects the tool’s interface from unauthorized access. Only administrators and developers should know this password.

Navigation Integration

phpLiteAdmin has been included in the Navigation Manager for convenience. You can access it from the admin dashboard like any other page link, or remove it from navigation if desired.

Note: phpLiteAdmin is not part of the app’s authentication system — it is a standalone utility. For security, remove or rename phpliteadmin.php before deploying to production environments.
